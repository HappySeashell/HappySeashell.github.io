## 前言
加了建站交流群之后发现像我一样的小白不在少数，甚至有人不知道什么是 html 和 markdown 就开始建了，中途遇到报错也不会改，百度之后可能更加茫然，看到的全是老版本的解决方案，或者看了也不懂。如果问大佬，大佬们会理解不了你为什么不会，因为太过基础了；即便有人告诉了你如何解决，可能也不会处理。

其实了解一下网页和编程的基础知识，这些都不难解决。
## 常见问题
{% note info HTML、CSS、JS是什么？ %}
### HTML、CSS、JS是什么？

- HTML: 简单来说，它是一种标记语言，描述了一个网页的主体内容。一个HTML文件中包含许多元素，这些元素以标签`<标签名></标签名>`的形式存在，标签可以层层嵌套，并且每个标签都有不同的功能。
  ![一个 HTML 文件的结构](https://www.runoob.com/wp-content/uploads/2013/06/02A7DD95-22B4-4FB9-B994-DDB5393F7F03.jpg)
  HTML 标签具有多个可以被设置的属性，使我们能更改它们的显示方式。有的标签还具有内置的方法，使我们可以进行某些特定的动作。
  设置一个HTML 元素的属性方式如下：
  ```html
  <!-- 设置一个div元素的class和id -->
  <div class="note" id="1"></div>
  ```
  其中，有两个重要的属性：`class` 和 `id`。我们可以将一个 `class` 赋给多个元素，但一个 `id` 只能赋给单个元素。如果我们想对一类或者一个元素进行处理，例如为它们赋予特定的样式，都要用到这两个属性。
- CSS：为了方便网页的管理，我们希望能把内容和样式分离。CSS 就是一种可以用于描述网页元素样式的语言。它由一系列元素选择器构成，每个选择器都对相应的元素进行处理。
  一个选择器的语法为：
  ```css
    /*在css中对一个p标签的样式进行更改*/
    p
    {
        text-align:center;
        color:black;
        font-family:arial;
    }
  ```
- JS：JS 全称为 JavaScript，是一种基于 HTML 的脚本语言，它可以对网页进行更加自由的处理。例如，改变网页内容和样式，生成一系列元素，进行数据处理，等等。JS 的语法和 C++、JAVA 较为相似，入门也较为简单。

{% note warning %}注意，HTML、CSS、JS 的语法各不相同，注释形式也不同。{% endnote %}
{% endnote %}

{% note info 什么是前端和后端？什么是静态博客？Hexo有后端吗？ %}
### 什么是前端和后端？
一个网页中，`.html`、`.css`、`.js` 这些用于显示页面的部分称为前端，此外，可能还需要与数据库进行交互，这部分称为后端，起到后台管理的作用。
### 什么是静态博客？
静态博客是指静态网页构成的博客。静态网页相对于动态网页而言，不需要经过服务器编译，直接加载到浏览器端进行显示。一般来说，静态博客相比于动态博客功能更少，但是也更加轻量。
### hexo有后端吗？
Hexo 就是一个静态博客。初始配置下，它是没有后端的，我们可以为它加上后端，例如我们文章的评论系统，就是有后台管理的。但是页面内容无法像动态博客一样实时显示，而要进行区域或页面的刷新才能改变。
{% endnote %}

{% note info 一个 hexo 项目里的文件可以动哪些，不可以动哪些？ %}
### 一个 hexo 项目里的文件可以动哪些，不可以动哪些？

``` bash
  #博客项目结构
  .
  ├─.deploy_git     # git部署文件，别动
  ├─public          # 生成的静态文件，不需要动
  ├─scaffolds       # 文章模板，懂的话可以动
  ├─node_modules    # hexo的js插件，不懂千万别动
  ├─source          # 用于存放文章、页面，可以动
  │   ├── _drafts   # 草稿，可以动
  │   ├── _posts    # 文章，可以动
  │   └── _data     # 用户自定义数据文件，可以动
  ├─themes          # 主题相关文件，除了里面的_config.yml之外，其他的不懂别动
  ├── _config.yml   # 全局配置文件，可以动
  └── package.json  # 项目依赖信息，不需要动
```

{% endnote %}

{% note info <code>_config.yml</code>文件是什么？在文件里搜到了很多个，应该修改哪一个？修改配置文件时老报错怎么办？ %}

### `_config.yml` 文件是什么？

`_config.yml`是一种`yaml`格式的配置文件，它由一系列键值对构成，规定了一个 hexo 项目里许多重要参数的值。

### 在文件里搜到了很多个，应该修改哪一个？

如果在文件里搜到了很多个，通过看路径可以区分：
- `blog/_config.yml`：hexo的配置文件
- `blog/themes/主题名称/_config.yml`：hexo主题的配置文件
- `blog/node_modules/.../_config.yml`：安装hexo时最初的配置文件，别动。

### 修改配置文件时老报错怎么办？

99% 的概率是语法错了。检查自己的语法，报错时会有相应提示。

几个容易出错的地方：
- yaml中的缩进代表层级，并且不允许 `tab` 缩进，只允许空格。相同层级的元素需要左对齐。
- yaml的键值对形式为 `key: value`，注意冒号 `:` 后有一个空格，并且不要使用中文冒号`：`。
- yaml中同一层级的键名不能重复，例如不能写：
  ```yml
  key: 
    child-key: value
    child-key2: value2
  key: 
    child-key: value3
    child-key2: value4
  ```
  两个 `key` 名字重复了。有的小白看教程时直接把别人的代码粘贴到 `_config.yml` 里，而不检查是否有重复的键，就会报错。要先找到键值对在文件中的对应位置，再对原有的键值对进行修改。
- 有可能改错地方。例如 next 的配置文件中，我们可以在注释里看到这样的警告：
  ```yml themes/next/_config.yml
        #! ==============================================================
        #! DO NOT EDIT THE FOLLOWING SETTINGS
        #! UNLESS YOU KNOW WHAT YOU ARE DOING
        #! See: https://theme-next.js.org/docs/advanced-settings/vendors
        #! ==============================================================
  ```
  不懂的话，这条注释下面的内容都不要改。在文件里搜索键名时，很容易犯这样的错误。
{% endnote %}
{% note info 为什么 <code>hexo s</code> 和<code>hexo g -d</code> 后的结果不一样？ %}
### 为什么 `hexo s` 和`hexo g -d` 后的结果不一样？
可能的原因与解决方案如下：
- 本地缓存未清理。在 `hexo g -d` 之前用 `hexo cl` 或者 `hexo clean` 来清理一下。注意，不是 `hexo c`。
- 浏览器缓存未清理。在设置里清理缓存文件，或者使用`ctrl`+`f5` 进行强制刷新（如果功能键设置了不需要`fn`，则是 `ctrl`+`fn`+`f5`）。
- `_config.yml` 中路径配置错误，导致CSS或者JS无法正常加载。
- Github 自动部署需要一定时间才能生效，耐心等个几分钟；Gitee 需要手动更新，否则不会生效。
{% endnote %}

{% note info 为什么我的网页加载速度很慢？ %}
### 为什么我的网页加载速度很慢？
在一些浏览器（Chrome、Edge等）里，我们在开发人员工具（`f12`打开）中可以看到一个叫`Lighthouse`的选项卡。它是一个用于测试网页前端性能的工具。我们可以通过它查看是哪些地方拖慢了网页加载，并进行优化。

常见的原因与解决方案如下：
- 静态资源（主要是图片）过多。尽量把图片放在图床上，而不是 git 项目里。
- 引用的本地CSS、JS文件过多。例如，自己写的本地CSS、JS文件可以压缩体积。JS可以用[工具](http://javascriptcompressor.com/)把几百行代码压缩成一行，并且将变量名设置得简短一些。同时为了保留可读性，备份原先的JS文件。自己写的本地CSS文件尽量合并到`main.css`中，例如在 NexT 主题中，可以把样式写到对应的`.styl`文件中，生成博客时，文件内容会自动合并到`main.css`里。
- 引用的外部资源加载过慢。可以利用 CDN 对 npm 包进行加速。例如，使用[jsDelivr](https://www.jsdelivr.com/)。
- 如果网页部署在服务器上，可能是服务器带宽过小，同时本地资源较多所致。
{% endnote %}

{% note info 为什么使用 hexo 命令报错？ %}
### 为什么使用 hexo 命令报错？
常见的原因与解决方案如下：
- 命令打错了。
- 在错误的目录里使用了命令。要进入一个 hexo 项目的目录下，才能用 `hexo s` 等命令。
- 如果连 `hexo -v` 都报错，说明 node.js 或者 npm 没有全局配置。解决方法参见百度。

{% note warning %}不要在 `node_modules` 文件夹里初始化一个博客项目！{% endnote %}
{% endnote %}
## 报错了怎么处理

报错分两种：Warning 和 Error。Warning 影响较小，一般不需要处理；Error 则必须处理，否则会打断程序运行。

### 本地 debug
运行 hexo 命令后出现错误时，命令提示符（cmd）会显示报错信息，我们可以通过这些信息来判断错误根源。大部分都比较容易判断。报错时，一个错误会引发一系列文件的报错。这时我们不需要慌，找到报错信息的最开头，就是错误的根源了。

报错会以如下的格式显示：
```text
FATAL Something's wrong. Maybe you can find the solution here: http://hexo.io/docs/troubleshooting.html
Error: fatal: Not a git repository (or any of the parent directories): .git

    at ChildProcess.<anonymous> (E:\Hexo\node_modules\hexo-util\lib\spawn.js:37:17)
    at emitTwo (events.js:106:13)
    at ChildProcess.emit (events.js:191:7)
    at ChildProcess.cp.emit (E:\Hexo\node_modules\cross-spawn\lib\enoent.js:40:29)
    at maybeClose (internal/child_process.js:850:16)
    at Socket.<anonymous> (internal/child_process.js:323:11)
    at emitOne (events.js:96:13)
    at Socket.emit (events.js:188:7)
    at Pipe._handle.close [as _onclose] (net.js:492:12)
```
其中，第一行是 hexo 的提示信息。我们的一些常见报错都可以在[报错文档](https://hexo.io/docs/troubleshooting.html)里查到。

第二行是报错原因，例如上面的例子里，报错原因是根目录下没有.git文件夹，一般是因为没有初始化 git 仓库，或者没有配置 git服务的用户名和邮箱所致。

第三行之后的是报错位置。一般来说，只有前 1~2 个报错位置是需要查看的，后面的都是链式反应，等前面的错误解决，后面的自然就好了。

### 浏览器端 debug
网页在浏览器中显示时，在浏览器的控制台（`f12`打开）中也会显示一些报错信息，这些信息往往和与外部资源的通信、数据库的交互有关。因此，如果我们发现网页部署时没有报错，但是有些资源的显示不正确，就该考虑到控制台查看报错了。

例如这个常见的报错：
```text
Failed to load resource: net::ERR_CONNECTION_TIMED_OUT
https://www.google-analytics.com/analytics.js:1
```
第一行为报错信息，代表加载资源失败，原因为与网络资源连接超时。这种报错一般是网络原因：外网资源被墙，资源链接填错，等等。

第二行为报错位置，这里代表与哪个网站进行通信时发生错误。

根据报错信息合理地 debug，就能解决大部分问题。如果不知道报错信息是什么意思，百度一下，你就知道。
